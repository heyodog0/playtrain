## 2. Environment-cost appendix (new, complete)

`\section{Where an Environment Step Goes}`, `app:envcost`. Title, figure, table.

**The result.** A step costs a fixed **6.1 us** plus its operations. Every
elementary operation costs 98-1304 ns, so throughput is set by how MANY
operations a game issues, not which kind. The suite spans 223x in steps/s.

| p5 primitive | ns | logic operation | ns |
|---|---|---|---|
| `background()` | **1304** | typed-array slot | 334 |
| `ellipse()` | 717 | allocation | 304 |
| `circle()` | 713 | entity update | 188 |
| 3-vertex shape | 545 | collision check | 130 |
| `quad()` | 430 | grid cell scan | 98 |
| `triangle()` | 367 | | |
| `line()` | 325 | | |
| `rect()` | 165 | | |
| `stroke()` / `fill()` | 123 / 121 | | |

- A filled **pixel costs 0.03 ns**, ~4,000x less than the call that draws it:
  resolution is nearly free, primitive count is not.
- `background()` is the most expensive operation measured and every game pays it
  once per frame. On pong and flappy_bird, clearing the screen costs more than
  the contents.
- Drawing is **15% (dodgeball) to 82% (maze)** of a step, with **no trend
  against total cost** — size sets magnitude, design sets the mix.

**Method, in `analogen-jaxbench`:**
- `tools/gen_probes.py`, `tools/gen_logic_probes.py`, `tools/gen_grid_probes.py`
  — probe environments that vary one quantity. Fits are linear at R^2 >= 0.9999;
  a 2-D grid shows no interaction and predicts held-out probes to **0.16%**.
- `tools/percmd_measure.py` — prices each primitive separately and counts each
  game per binding. **Run this, not the older flat-rate path.**
- `tools/plot_env_cost.py`, `tools/mktab_envcost.py` — figure and table.
- `tools/ablate_qbert.py` — mechanic ablation (see below).

**Native counters** (`playtrain/native/qjs/qjs_vec_host.cpp`, `cf4cc51`):
per-binding draw counts via `vec_set_count_draws` / `vec_draw_count(i)`.
Validated: `probe_draw_N` returns exactly `2N+1` (N fill + N rect + 1
background).

## 3. Things that were WRONG and are now fixed — do not reintroduce

- **A flat "p5 command" rate is not adequate.** Calibrated on `rect`, it
  undercharged quad/ellipse games up to 4x and misfiled the difference as game
  logic. qbert.v2 read as 75% logic; it is 53% drawing. Every primitive the
  suite calls is now priced individually, with **no fallback rate**.
- **`vertex()` is not separable.** Sweeping vertices inside one `beginShape`
  grows a single polygon, so the slope measures fill AREA. It produced 1207 ns
  per vertex, a NEGATIVE begin/end pair, and billed qbert at **137% of its own
  step**. The shape API is charged per polygon (545 ns for 3 vertices), scaled
  by the game's vertices-per-shape. **The >100% check is the guard — keep it.**
- **`bench_render_split.py` is superseded.** Its logic/draw split is confounded:
  the `NODRAW` macro returns from the binding BODY, so draw-call dispatch lands
  on the logic side. Do not revive it; the per-binding counter replaced it.
- **Stacked bars on a log axis misreport shares.** A segment's height is the
  ratio across it, not its share of the total. qbert.v2's 75% logic looked like
  the smaller piece. Composition panels are linear 0-100%.
- **frame_skip must match between probes and games.** The probes run
  `frame_skip=1` and pay the once-per-step obs readback every tick; a
  `frame_skip=4` derivation amortises it over four. Mixing them made flappy_bird
  measure FASTER than an empty environment — a physical impossibility, and the
  tell that the units were wrong.

## 4. Cluster / tooling traps paid for today

- **`fasrc "..."` strips quote characters from embedded scripts.**
  `price.pop("shapepair")` arrived as `price.pop(shapepair)`, the job died with
  NameError, and the previous (bad) JSON stayed in place looking plausible.
  **Send any non-trivial script base64-encoded** and `compile()` it before
  submitting.
- **A superseded run renamed with a suffix sorts AFTER its replacement.**
  `icnnppo_qbert_v2_s0_partial94M` > `icnnppo_qbert_v2_s0`, so the
  latest-dir-wins tiebreak in `plot_main_composite.py` silently preferred the
  stale 94M runs. `_EXCLUDE` now covers `_partial`, `_failed`, `_dead`
  (`a04cbef`). **The tell was a byte-identical PNG after a rerun.**
- **Select runs by config content, not directory prefix.** Prefix globs dropped
  a whole arm twice (the `_natfix` seeds, then the IMPALA-CNN PPO seeds), each
  time rendering as a curve with no band rather than an error.
- Slurm walltime: qbert.v2 needs **6 h** for 100M PPO steps (~6,900 sps), not 4.

## 6. Open, none blocking

- **JS function profiler** (`analogen-jaxbench/tools/prof_game.py`, host hooks
  `ea214d3` + `2b9038e`). Works and preserves determinism: the JS only reports
  WHICH function it is entering (`__pe`/`__px`) and C++ holds the clock, so no
  time value enters the interpreter. Self-time via a shadow call stack, so
  shares sum to ~100%. **But it adds ~850 us to qbert.v2's 1572 us step**,
  concentrated in the most-called functions — `getIsoPos` at 1159 calls/step is
  mostly measuring its own instrumentation. **Needs a per-call overhead constant
  measured from a probe before any number is quoted.** Also: function names
  differ per game, so it cannot feed a cross-game legend — use it as a worked
  example, not a panel.
- `tab:hyperparams` — re-read now that both trainers really are IMPALA-CNN
  everywhere.

`playtrain/examples/games/js/qbert.v2.js` and `breakout.v4.js` have
**uncommitted local modifications** (a `renderGame` rewrite: diagonal sweep, no

slower code and will not reproduce these numbers.
