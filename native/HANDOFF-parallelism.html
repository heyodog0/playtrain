What we found pushing single-env — and why it's a wall

Four probes, each cleanly measured. Together they say: the per-env, per-thread frontier is essentially closed.

The bottleneck bifurcates by game profiled

Per-frame split (Apple M4, QJS_NODRAW / jsnoop probes): miner is rasterizer-bound (~47%); coinrun is logic-bound (~86%). The FFI crossing is only ~1% — which refuted the "collapse the per-primitive boundary crossings" idea (a retained-mode command buffer would save almost nothing).

The rasterizer fill is already SIMD no gain

The opaque span loop compiles to NEON dup.4s + paired 128-bit stp q stores — 16 pixels/iteration, scalar tail. Hand-writing std::simd yields nothing. miner's rasterizer cost is per-fill fixed overhead across many small tiles, not scalar loops — only a native tilemap primitive or a block-rect fast path touches that (and both need game-code changes).

Interpreter micro-tuning is dead 0% speedup

Opcode profile: hot ops are get_loc_check (~19%), get_var (~15%). We built & validated a bit-exact TDZ-check elimination pass — it downgraded 12.4% of qbert's dispatches checked→unchecked and moved throughput 0%. The check is free; the cost is dispatch + value-plumbing, which tuning can't remove. quickjs-ng has no TDZ pass and abandoned inline caches (#244) — open, but low-ROI. Only get_var caching / superinstructions might show single digits.

Reusable patches: native/archive/profiling/{opcode-profiler,tdz-eliminate}.patch.

Single-env, single-thread throughput is tapped out.

Browser, boundary, readback: peeled. Fill: already vectorized. Interpreter: constant-factor and empirically flat. Further per-env gains are structural and costly (native tilemap = game rewrites; AOT transpile = fragile, per-game, bit-exact-gated).

Why this is the right target (and per-env speed isn't)

Training is learner-bound: the env already produces ~7–8× more steps than the learner consumes, GPU sits at ~42% util. So single-env speed barely moves end-to-end training wall-clock. But for evaluation, dataset collection, and human-baseline runs, aggregate throughput is the wall-clock — and that's capped ~3–4× below what the hardware can do. This is the highest-leverage lever left, and unlike the interpreter it plausibly has a real multiple in it.
